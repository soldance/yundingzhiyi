# 云顶之弈对局决策助手

> **不推荐"当前强势阵容"，而是回答"这套阵容为什么强、依据是哪条改动"。**

[云顶之弈](https://teamfighttactics.leagueoflegends.com/)（Teamfight Tactics）对局决策助手：基于**当前版本补丁**推导阵容强度，给出可溯源的阵容推荐、装备分配、站位与经济运营建议。

当前适配赛季：**Set 18「苍林秘境」** ｜ 最新补丁：**18.3**

---

## 这个项目解决什么问题

市面上已经有很多阵容推荐工具，但它们大多是**第三方统计数据的搬运**——列出使用率和平均名次，玩家知道"什么强"，却不知道为什么，也无法判断某个具体改动对自己手上的阵容意味着什么。

云顶还有一个特殊性质：**每约 4 个月更换赛季，全部英雄、羁绊、装备被清空重建**。这意味着任何依赖静态数据的工具都会在换季时静默失效——它仍然在输出阵容，只是输出的是上上个赛季的。

本项目从这两个缺口出发：

| 常见做法 | 本项目 |
|---|---|
| 展示使用率 / 平均名次 | 展示**推导过程**：补丁改了什么 → 影响哪些核心卡 → 阵容强度如何变化 |
| 结论无出处 | 每条建议可展开查看**依据的补丁条目**，附官方公告外链 |
| 换季静默失效 | **版本指纹校验**，赛季不一致时直接阻断而非降级 |
| 大模型凭记忆作答 | **事实来自数据，判断来自模型**，边界严格划分 |

## 核心设计

### 1. 事实与判断分离

云顶的所有事实（谁是 5 费、哪个羁绊在几人口激活、某件装备加多少属性、这个补丁削了谁）都是外部给定的、有唯一正确答案的。因此本项目强制执行一条边界：

> **凡是能确定性计算的，绝不交给语言模型。**

英雄查询、羁绊激活判定、升级经验与刷新概率、补丁改动到阵容强度的增量计算——全部由代码完成。语言模型只负责两件事：把玩家的自然语言问题翻译成结构化查询，以及在事实确定的前提下做取舍判断。

### 2. 阵容是推导出来的，不是录入的

```
基准线（每赛季人工维护一次）
  阵容骨架：名称、核心英雄、装备分配、站位、成型曲线
        ↓
增量线（每个补丁重算）
  补丁改动清单 → 受影响英雄 → 所属阵容与角色 → 阵容强度增量
        ↓
  当前版本阵容梯队
```

好处是**可审计**（每条梯队结论都能追溯到具体改动）、**维护成本低**（新补丁只需处理差异，不必重新评估全部阵容）、以及**不会出现"界面显示 18.5 但阵容还是 18.1 评估的"这种静默失败**。

### 3. 幻觉三道闸门

语言模型凭空编造一个英雄或羁绊，玩家往往不易察觉。本项目对模型输出做结构化校验：

1. **输入侧**：将当前赛季的英雄、羁绊、装备名册作为白名单注入提示词，模型只能在封闭集合内选择
2. **输出侧**：要求输出结构化 JSON，后端逐项比对数据文件；不存在的名称标记出来而非静默丢弃
3. **工具约束**：提供确定性的羁绊核验工具，并规定给出终局阵容前必须先调用

## 架构

```
┌──────────────────────────────────────────────────────┐
│  前端  Vue 3 + Vite + Tailwind                       │
│  阵容总览 · 局面咨询 · 数据速查                        │
└───────────────────────┬──────────────────────────────┘
                        │ JSON / SSE
┌───────────────────────▼──────────────────────────────┐
│  后端  Node 22 + Hono + TypeScript                   │
│  ├─ 数据访问层（唯一读入口）                           │
│  ├─ 阵容强度推导（补丁增量叠加）                       │
│  ├─ LLM 代理（密钥仅存后端）                          │
│  └─ 输出校验闸门（拦截幻觉）                           │
└───────────────────────┬──────────────────────────────┘
                        │
┌───────────────────────▼──────────────────────────────┐
│  数据层                                              │
│  ├─ 游戏数据   JSON 数据包，按赛季分目录               │
│  │             来源：Community Dragon（含官方中文）    │
│  ├─ 知识层     Markdown + git（策略/梯度/运营节奏）    │
│  └─ 动态数据   SQLite（会话、对话历史）                │
└──────────────────────────────────────────────────────┘
```

### 数据来源

| 数据 | 来源 | 说明 |
|---|---|---|
| 英雄 / 羁绊 / 装备 / 数值 | [Community Dragon](https://raw.communitydragon.org/) | Riot 官方数据源，**原生中文**，无需自行维护翻译 |
| 棋子头像等资源 | Community Dragon 资源目录 | 直连引用，不下载到仓库 |
| 补丁说明 | Riot 官方公告 | 抓取原文后结构化，每条保留出处 |

## 已知的数据陷阱

这些是在实际验证数据源时踩到并记录下来的，写在这里是因为它们都属于**静默失败**——不报错，但结果是错的：

1. **Community Dragon 的 `setData[].name` 字段不可信**。当前赛季数据的该字段实际写着 `"Set10"`。必须用 `number` 字段定位，再用英雄 `apiName` 前缀二次校验。
2. **接口返回的是历史上所有赛季快照的合集**，不是当前赛季，需要自行切出最新快照。
3. **非英雄条目混在英雄列表里**（纹章之书、训练假人、锻造器等道具），需要通过费用与羁绊字段过滤。
